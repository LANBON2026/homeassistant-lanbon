# LANBON

The **LANBON** integration connects Home Assistant to a LANBON Mesh **root** panel on your LAN. Control and state use the panel's local HTTP/WebSocket API (port **8765**). Child Mesh nodes appear as devices linked through the root (`via_device`).

Cloud MQTT is **not** required for local control.

## Prerequisites

- A LANBON panel acting as Mesh **root** (level 1) with firmware that exposes local API `proto: 1`
- Home Assistant **2026.3** or newer (local `brand/` icons; integration targets this baseline)
- Panel and Home Assistant on the same network (mDNS helps discovery; manual IP always works)

## Configuration

{% include integrations/config_flow.md %}

You need:

| Field | Description |
| --- | --- |
| Host | LAN IP of the Mesh root panel |
| Port | Local API port (default `8765`) |
| Token | 32-character hex Bearer token from the panel |

The token is printed in the panel serial log when the local API starts, for example:

```text
HA local API up (mesh root). token=xxxxxxxx
```

It is also advertised in mDNS TXT (`_lanbon._tcp`) as `token=`.

### Zeroconf discovery

If Home Assistant and the panel share a working mDNS path, a discovery notification appears. Confirm and (if needed) paste the token.

## Entities

Depending on panel type, the integration creates:

- **Switch** — multi-gang switch channels
- **Light** — dimmer brightness
- **Cover** — curtain open/close/stop

Channel names sync from the panel (`channel_names`). You can rename a switch channel with the `lanbon.set_channel_name` service or by renaming the entity in the UI (pushed back to the panel).

## Removing the integration

{% include integrations/remove_device_service.md %}

1. Go to {% my integrations title="Settings → Devices & services" %}
2. Select **LANBON** → the config entry → **Delete**
3. Optionally remove leftover entities from the entity registry

No panel-side factory reset is required; the Bearer token remains on the device until regenerated by firmware/NVS.

## Local API

Protocol details (frozen contract): see the integration repository `docs/API.md` (`proto: 1`).

## Troubleshooting

- **Cannot connect** — ping the panel IP; ensure port `8765` is reachable; confirm the panel is Mesh root
- **Invalid token** — copy a fresh token from serial log or mDNS TXT (token changes if NVS is wiped)
- **Not Mesh root** — only the root exposes the local API
- **No mDNS** — Docker/WSL2/VLAN isolation often breaks discovery; add the integration manually by IP
